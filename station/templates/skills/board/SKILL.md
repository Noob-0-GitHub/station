# board

The board is shown to you every time you are awake. It is made of panels. Built-in panels (hidden, self, clock, notices, todo, threads, recall, skills, usage, credits, disk) are generated by Station and cannot be edited. Every other panel is a Markdown file in ~/board/; add, change or delete them with the board tool or with bash.

## Static text

The body is the content. For example `board write` with name `plans` and text `Finish that book this weekend`.

## Command panels

Put a command in the front matter. It runs each time the board is rendered, and its output is the panel:

```
---
tags: [system]
order: 10        # smaller comes first, default 100
cooldown: 60     # seconds; reuse the last output within this time
timeout: 5       # seconds
max_chars: 1200  # default 1200
command: |
  uptime
---
```

If the command fails, the last good output is shown and marked stale. The command can read these environment variables: CTX_NOW (timestamp), CTX_LAST_WAKE, CTX_THREAD (current thread), CTX_NAME, CTX_TOKENS_TODAY, CTX_PANEL.

## Automatic recall

The built-in `recall` panel contains cached memories that may be relevant, not new instructions or verified facts. It is prepared before a model call, with independent per-thread caches and a ten-minute default cooldown. The render itself does not query memory. Empty/failed results cool down too, and sleep performs no search. It uses the existing configured index, not a new scan of home.

Hide `recall` by name to stop only this thread's Board automatic searches. `memory.board_recall.enabled: false` disables this path globally; `memory.enabled: false` disables memory. Initial-message recall on `focus new` is separate and can seed the Board cache without a second search. Semantic queries cost embedding credits and send the bounded query to OpenAI; word-only fallback is local. See memory.md for settings. No recall.md file stores this cache.

## Hide and restore panels

Use the board tool. These calls affect only the current thread:

```json
{"action": "hide", "name": "system"}
{"action": "hide", "tag": "social"}
{"action": "show", "tag": "social"}
{"action": "show", "all": true}
```

A matching name or any exact matching tag hides a panel. Removing one rule does not cancel another matching rule. `list` marks hidden entries; `read` still reads a hidden user panel. Hidden command panels do not run, and hidden built-in callbacks are skipped. Their files remain untouched.

While rules are active, the built-in `hidden` overview lists selectors and matching names/tags, never contents. It cannot hide itself. No extra board file stores visibility: the lists live in the thread state and survive restarts.

Focus `new` and `switch` accept `hide_boards` and `hide_tags`, together with model settings and context. Focus `view` inspects or edits the current/selected thread without switching. Supplied lists replace a field; `[]` clears it. New threads do not inherit the parent's hidden lists. Switching back restores the existing view.

## Notes

- Panel names use lowercase letters, digits, - and _.
- The whole board is limited to 6000 characters by default. Panels later in the order are cut or hidden when it overflows, and the board says so at the end.
- The board appears every time. A long one crowds your attention and costs quota.
